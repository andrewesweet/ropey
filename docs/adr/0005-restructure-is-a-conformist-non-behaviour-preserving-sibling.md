# Restructure is a conformist, non-behaviour-preserving sibling (Rewrite)

rope's `Restructure` rewrites every site matching a `pattern` into a `goal`, with `${wildcard}` placeholders narrowed by per-wildcard constraints. It does not fit the model the other eleven tools share: it is **not** addressed by a Location, and it is **not** behaviour-preserving — the pattern→goal equivalence is the caller's assertion, not rope's guarantee. We admit it as a **Rewrite**: a sibling of Refactoring, not a kind of it. It reuses the entire foundation (Search Scope, Freshness, Blast Radius, Dry Run / Live Run, Structured Failure, Uncertain Occurrence) but is addressed by a **Pattern** and **Goal** rather than a Location, and it makes no equivalence claim. For this one sibling, ropey is a **Conformist** to rope's *published* Restructure language: Pattern, Goal, and Wildcard cross the tool boundary verbatim — the single, deliberate relaxation of the "no rope vocabulary crosses" rule (ADR 0004), justified because these are rope's *published* vocabulary, not its *internal* model (Offset, ChangeSet, PyObject), which stays walled off.

## Considered Options

- **Widen "Refactoring" to include it** — redefine the core term as "intent-preserving" so Restructure qualifies. Rejected: "behaviour-preserving" is load-bearing across CONTEXT.md and four ADRs; weakening it to admit one tool dilutes the guarantee the other eleven actually provide, and a future reader could no longer trust "Refactoring" to mean *safe*.
- **Force a Location anchor** — require the agent to point at a Range ("restructure within this selection") so Restructure conforms to the LSP input language. Rejected: the transformation is structural (pattern→goal across the project), not positional; an anchor expresses neither the match template nor the replacement, and rope's own model is pattern-addressed. A coordinate would be a fiction.
- **ACL-wrap the Restructure DSL** — invent ropey coinages for pattern/goal/wildcard and translate. Rejected: these are rope's *published*, UI-facing language (rope's pydoc: `make_checks` exists "to ease writing a UI"), the same category as LSP's published Position/Range — conform, don't re-coin. Inventing synonyms would be a translation tax with no isolation benefit, since the terms are stable and intended for consumers.
- **Conformist, non-behaviour-preserving sibling (chosen)** — keep "Refactoring = behaviour-preserving" intact, quarantine the behaviour-changing semantics under a clearly-labelled Rewrite, and conform to rope's published DSL while keeping rope *internals* behind the ACL.

## Consequences

- **A second input language.** Rewrite is addressed by a Pattern (match template) + Goal (replacement template) + per-Wildcard **Match Constraints** — not a Location. ADR 0001 ("LSP coordinates as THE input language") gains a pointer here: Location is universal *except* for this Pattern-addressed sibling. This is the first tool that is neither point nor selection; the tool-description standard and its CI test grow a third (Pattern-addressed) input category, exempt from the 0-based/UTF-16 coordinate checks.
- **The ACL seam is published-vs-internal, not rope-vs-not.** Pattern, Goal, and Wildcard cross verbatim. The sole coinage is **Match Constraint** (rope's generic `args` renamed). A constraint may name a *user* symbol (`type=myapp.models.User`) but never a rope-internal type (`rope.base.pyobjects.PyObject`). rope's custom-wildcard *classes* — which would program against rope's internal AST — stay out (ACL, boundary-testability, YAGNI); Match Constraint is the designated extension point if matching must grow, as a new ropey-published key.
- **Safety shifts from tool-proven to agent-asserted, so every match is surfaced.** Because nothing is proven, the result enumerates every **Match Site** (a Location where the Pattern fired), on both Dry and Live runs — the over-match audit surface, generalizing the Uncertain Occurrence contract (ADR 0003) from uncertain matches to *all* matches. The file-level Blast Radius cannot reveal over-matching *within* an in-scope file; the Match Site list can. No file contents are returned (token rule); `git diff` after a Live Run is the exact-text verifier, and a clean working tree before a Rewrite Live Run is doubly emphasised. The transaction mechanism is unchanged — the uniform `apply` flag, no bespoke two-phase handshake — but the tool description steers Dry-Run-first more firmly, and leans conservative on triggering (over-using the unproven tool is the worse error: prefer a dedicated Refactoring whenever one fits).
- **`unsure` is the pre-adjudication knob over the same surfacing contract.** Each Match Site carries a certainty: *proven* (constraints statically satisfied, or unconstrained) or *unsure* (a type/object/instance constraint unprovable, common under dynamic typing). Without `unsure`, unsure sites are **not** rewritten but **are** surfaced for the agent to adjudicate; with `unsure` (per wildcard), they **are** rewritten and **stay flagged**. Nothing silently dropped, nothing silently applied as if certain — ADR 0003's whole-truth contract, with adjudication moved before the apply instead of after.
- **Rewrite is the one tool that can mechanically emit broken code.** rope guarantees valid syntax for the behaviour-preserving refactorings; template substitution does not. Two guards follow: a malformed Pattern/Goal (won't parse, no wildcards, or a Goal `${wildcard}` absent from the Pattern) is a Structured Failure; and the server parse-checks each changed module against the computed Change Set — a Rewrite that would produce unparsable Python is a Structured Failure naming the file and parse location, caught at Dry Run so it is never applied. Zero matches, by contrast, is a **loud successful empty result** ("0 Match Sites"), not a failure — it ran and found nothing.
- **Goal-introduced names need imports the server will not infer.** A `goal` may reference a name the target module does not import; rope's `imports` parameter adds them (deduping existing ones) and is exposed. The server does not analyse the Goal to infer missing imports — that is navigation/type-checking, ty's job — so an omitted import yields un-importable code; the tool description states this responsibility.
- **Reverse translation becomes load-bearing.** Match Sites report Ranges *back* to the agent, so Rewrite is the first tool to exercise offset → LSP UTF-16 Position/Range translation at scale (existing tools mostly *consume* Locations). A non-ASCII Match Site must report a correct UTF-16 Range or the agent cannot feed it to ty — a mandated integration-test case.
- **Delivered as PRD 0002**, a single tool in a single phase (the parent PRD's Phase 5), consuming the foundation by reference. The safety surface (constraints, Match Site + `unsure` surfacing, parse guard) is inseparable from the capability and lands together — shipping pattern/goal without the constraint surface would be the over-match footgun with its safety catch removed.
